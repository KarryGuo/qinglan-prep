# 青蓝备课 技术架构方案

版本 v0.2 · 2026-08-16 · 供编码实现与参赛答辩使用（v0.2 变更：数据库由 Neon Postgres 更换为 Turso）

青蓝备课是一个面向中小学教师的备课 Agent：教师输入课题与学情，系统按"诊—设—生—思"四个阶段完成学情诊断、依标设计、备课包生成，并在课后接收作业数据生成教学反思、写回学情记忆。本文档定义支撑这一闭环的全部技术决策。

## 1. 设计约束

四条约束决定所有选型：

1. 评委可验证。产品以在线 URL 交付，任务链路的每一步（思考、工具调用、结果、依据）都留痕并可视化，答辩时可以打开后台看 Agent 的完整执行过程。
2. 低成本。部署在 Render 免费档，数据库用 Turso 免费档，模型用低价国产模型，单次备课的模型成本控制在 0.1 元以内。
3. 快速实现。单仓库、单服务、单数据库，不引入微服务与消息队列；Agent 编排自研约 300 行 TypeScript，不引入 LangChain 等重框架。
4. 合规优先。教师端产品，不直接采集未成年人个人信息；演示数据全部为模拟或公开资料整理，所有输出附"供备课参考"声明。

## 2. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│  表现层  Next.js App Router（SSR + React）                    │
│  落地页 / 备课流程 / 备课包 / 反思 / 学情记忆 / Agent 过程页      │
├────────────────────────────────────────────────────────────┤
│  接口层  REST（JSON）+ SSE（流式事件）                         │
│  /api/lessons  /api/lessons/[id]/run  /api/lessons/[id] ...  │
├────────────────────────────────────────────────────────────┤
│  Agent 编排层                                                │
│  Orchestrator（Plan-Execute-Reflect 循环）                    │
│  四个阶段：diagnose / design / generate / reflect             │
│  工具注册表 · 上下文管理器 · 事件发射器 · 模式校验器              │
├───────────────┬────────────────────────────────────────────┤
│  能力层        │  知识层                                      │
│  LLM 推理      │  课标库 CurriculumClause                     │
│  （OpenAI 兼容）│  教材结构库 TextbookNode                     │
│  多模态识别     │  题库 Question                               │
│  （二期）      │  学情记忆 ClassMemory                         │
├───────────────┴────────────────────────────────────────────┤
│  数据层  Turso（SQLite/libSQL，Prisma ORM）· 文件仅临时解析      │
├────────────────────────────────────────────────────────────┤
│  部署层  GitHub（代码与文档）→ Render（Web 服务）→ Turso（数据库）│
└────────────────────────────────────────────────────────────┘
```

各层职责：

- 表现层负责四阶段向导、备课包阅读、溯源面板与 Agent 过程时间线，全部为服务端渲染加少量客户端交互组件。
- 接口层只做两件事：读写 Lesson 状态，以及以 SSE 推送阶段执行事件。
- 编排层是核心，持有阶段状态机、工具注册表和提示词模板，不持有任何业务数据。
- 知识层四张表在首次启动时由种子脚本写入，随教材改版手动更新版本号。
- 数据层为单个 Turso 数据库（SQLite 兼容的 libSQL），业务数据与知识数据同库，降低运维面。

## 3. 技术选型与理由

| 选型 | 备选 | 理由 |
|---|---|---|
| Next.js 15 App Router + TypeScript | Vite SPA + Express | 单服务即可同时承载页面与 API，Render 免费档只跑一个服务；SSR 让落地页首屏即产品叙事 |
| Tailwind CSS，不引 UI 库 | shadcn/ui | 页面数量少（7 个），手写组件更少依赖、更可控 |
| Prisma + Turso（免费档，libSQL） | Neon Postgres、本地 SQLite | Render 免费档磁盘是临时的，本地 SQLite 每次部署丢数据；Turso 免费档给 5GB 存储、每月 5 亿行读/1000 万行写，且**没有计算时长配额**——Render 保活 ping 不会像 Neon 那样把数据库计算一直唤醒而烧穿 100 CU-hours；读请求无休眠冷启动，评委首查即快。Prisma 6.2+ 的 SQLite 连接器已支持 Json 与 Enum，运行时经 `@prisma/adapter-libsql` 接入，数据模型无需降级 |
| 自研编排（function calling 循环） | LangChain / LangGraph | 链路只有"四阶段 × 工具调用"一种形态，自研约 300 行，答辩时能逐行讲清；重框架反而增加解释成本 |
| SSE 流式 | WebSocket | 事件单向推送，SSE 对代理与无状态部署更友好，前端一个 EventSource 搞定 |
| DeepSeek（默认）/ Qwen-Max（可切换） | GPT 系列 | OpenAI 兼容协议，中文教学文本质量足够，价格约为海外模型的 1/10；环境变量切换，不锁定 |

## 4. Agent 编排设计

### 4.1 阶段状态机

Lesson 的 status 字段取值：`diagnose → design → generate → delivered → reflected`。每个阶段遵循同一节奏：运行（run）→ 教师确认或修改（confirm）→ 进入下一阶段。教师可以在确认时附带修改意见，意见作为用户消息注入下一轮对话。课后反思（reflect）在 delivered 之后随时可触发，可多次触发，每次都会写回学情记忆。

### 4.2 Plan-Execute-Reflect 循环

每个阶段的执行是一个有上限的工具调用循环：

```ts
async function runStage(lessonId: string, stage: Stage, emit: Emitter) {
  const ctx = await buildContext(lessonId, stage);   // 课题、学情描述、记忆、上阶段产物
  const messages = [systemPrompt(stage, ctx), userPrompt(stage, ctx)];
  for (let turn = 0; turn < MAX_TURNS; turn++) {     // MAX_TURNS = 6
    const res = await llm.chat({
      model: env.LLM_MODEL,
      messages,
      tools: TOOLS[stage],
      tool_choice: "auto",
    });
    if (res.tool_calls?.length) {
      emit({ kind: "tool_call", payload: res.tool_calls });
      for (const call of res.tool_calls) {
        const out = await executeTool(call);          // 工具注册表分发
        emit({ kind: "tool_result", payload: { name: call.name, out } });
        messages.push(toolResultMessage(call, out));
      }
      continue;
    }
    const parsed = validateStageOutput(stage, res.content);
    if (parsed.ok) {
      await persist(stage, lessonId, parsed.value, extractCitations(parsed.value));
      emit({ kind: "stage_done", payload: parsed.value });
      return;
    }
    messages.push(correctionMessage(parsed.errors));  // 一次纠正机会
  }
  emit({ kind: "error", payload: { reason: "max_turns" } });
}
```

Plan 体现在系统提示词中给定的阶段工作步骤；Execute 是工具调用与最终结构化输出；Reflect 有两处：阶段内的模式校验与纠正，以及课后 reflect 阶段对整节课的复盘并写回记忆。

### 4.3 工具注册表

| 工具 | 入参 | 出参 | 使用阶段 |
|---|---|---|---|
| search_curriculum | subject, grade, query, limit | 课标条目（id, code, text） | design, generate |
| search_textbook | subject, grade, lessonTitle | 教材节点（前置知识、易错点、要点） | diagnose, design |
| search_questions | subject, grade, knowledgePoint, tier, limit | 题目列表 | generate |
| read_class_memory | classMemoryId | 班级学情画像 | diagnose, reflect |
| write_class_memory | classMemoryId, patch | 更新后的画像 | reflect |
| parse_scores | csvText | 结构化成绩（题号、正确率） | diagnose, reflect |

工具均为服务端纯函数，直接查 Prisma，无外部网络调用，失败即抛错并由编排层记录为 error 事件。

### 4.4 上下文与记忆

单次阶段调用的上下文由 `buildContext` 组装：课题四要素（学科、年级、教材版本、课题）、教师学情描述、上阶段产物摘要、班级记忆（仅 diagnose 与 reflect 注入）。检索类工具默认 limit=3，控制 token 预算在单次调用 12k token 以内。

学情记忆是产品壁垒的数据载体：`ClassMemory.profile` 存弱点了表（名称、严重度、最近证据、最近更新时间）与已解决弱点列表。reflect 阶段通过 write_class_memory 增量更新，下一次 diagnose 先读记忆再结合本次输入，实现"越用越懂你的班"。

### 4.5 流式事件协议

SSE 事件类型：

| 事件 | 含义 | data 示例 |
|---|---|---|
| stage_start | 阶段开始 | {stage:"diagnose"} |
| thought | 模型一轮推理的文本摘要 | {text:"先查教材节点…"} |
| tool_call | 发起工具调用 | {name:"search_textbook", args:{...}} |
| tool_result | 工具返回 | {name:"search_textbook", out:{...}} |
| delta | 最终产物的增量文本（可选） | {text:"…"} |
| confirm_required | 信息不足，请求教师补充 | {questions:["…"]} |
| stage_done | 阶段产物定稿 | {output:{...}} |
| error | 失败 | {reason:"llm_timeout"} |

所有事件同时写入 RunEvent 表，/prep/[id]/trace 页面按时间线回放，答辩与复盘都用它。

### 4.6 失败处理

- LLM 超时或 5xx：指数退避重试 2 次，仍失败发 error 事件，前端提示"稍后重试"，不伪造结果。
- 最终输出未通过 JSON Schema 校验：追加一次纠正消息（附校验错误列表）；二次失败发 error 事件。
- 工具返回空（如课题不在教材库）：不静默跳过，发 confirm_required 让教师补充前置知识描述，并在产物中标注"依据由教师提供"。
- 模型对不确定内容：提示词要求输出 confidence 字段，低于阈值前端显示"建议人工核对"角标。

## 5. 数据模型

```prisma
generator client { provider = "prisma-client-js" }
datasource db    { provider = "sqlite"; url = env("TURSO_DATABASE_URL") }

model Teacher {
  id        String        @id @default(cuid())
  name      String
  prefs     Json?
  lessons   Lesson[]
  memories  ClassMemory[]
}

model ClassMemory {
  id        String   @id @default(cuid())
  teacherId String
  teacher   Teacher  @relation(fields: [teacherId], references: [id])
  className String
  profile   Json     // { weakPoints:[{name,severity,evidence,updatedAt}], resolved:[...] }
  lessons   Lesson[]
  updatedAt DateTime @updatedAt
}

model Lesson {
  id             String      @id @default(cuid())
  teacherId      String
  teacher        Teacher     @relation(fields: [teacherId], references: [id])
  classMemoryId  String?
  classMemory    ClassMemory? @relation(fields: [classMemoryId], references: [id])
  subject        String
  grade          String
  textbook       String
  title          String
  classDesc      String
  status         String      @default("diagnose")
  profileJson    Json?       // diagnose 产物
  designJson     Json?       // design 产物
  packageJson    Json?       // generate 产物
  reflectionJson Json?       // 最近一次 reflect 产物
  citations      Citation[]
  events         RunEvent[]
  createdAt      DateTime    @default(now())
  updatedAt      DateTime    @updatedAt
}

model Citation {
  id       String @id @default(cuid())
  lessonId String
  lesson   Lesson @relation(fields: [lessonId], references: [id])
  stage    String
  citeType String // curriculum | textbook | classdata | teacher
  ref      String // 人读引用，如"课标·第三学段·阅读与鉴赏"
  sourceId String // 知识表主键；teacher 类型为空
  snippet  String
}

model RunEvent {
  id        String   @id @default(cuid())
  lessonId  String
  lesson    Lesson   @relation(fields: [lessonId], references: [id])
  stage     String
  kind      String
  payload   Json
  createdAt DateTime @default(now())
}

model CurriculumClause {
  id      String @id
  subject String
  stage   String // 学段，如"3-4年级"
  code    String // 如"语文·3-4年级·阅读与鉴赏·2"
  text    String
}

model TextbookNode {
  id          String @id
  subject     String
  grade       String
  volume      String
  lessonTitle String
  keyPoints   Json   // string[]
  prerequisites Json // string[]
  commonErrors  Json // string[]
}

model Question {
  id             String @id
  subject        String
  grade          String
  knowledgePoint String
  tier           String // basic | advanced | extension
  text           String
  answer         String
}
```

Citation 是溯源的载体：备课包界面上每个设计点可点击展开引用列表；RunEvent 是过程留痕的载体，两者共同满足评审对"结果可追溯"的要求。

Turso 适配要点（编码时照此实现）：

- Prisma 版本锁定 6.2 及以上（SQLite 连接器自 6.2 起支持 Json 与 Enum，上述模型无需改动字段类型）。
- 运行时 `src/lib/prisma.ts` 使用 driver adapter 接入：`@prisma/adapter-libsql` 的 `createClient({ url: env.TURSO_DATABASE_URL, authToken: env.TURSO_AUTH_TOKEN })` 传给 `new PrismaClient({ adapter })`。
- Prisma CLI（`db push`、seed）直连 Turso：`TURSO_DATABASE_URL` 写成带 token 的完整串 `libsql://<db-name>.turso.io?authToken=<token>` 即可被 CLI 识别；本地开发用同一个串，零配置。
- SQLite 无 `ILIKE`，检索用 `LIKE`（对 ASCII 天然不区分大小写，中文不受影响）；Json 字段按整对象读写，不使用数据库侧 JSON 路径过滤。

## 6. 接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/lessons | 创建 Lesson，入参为表单四要素 + 学情描述 + classMemoryId，返回 {id} |
| GET | /api/lessons/[id] | 读取 Lesson 全量状态（含产物、引用、事件） |
| POST | /api/lessons/[id]/run | body {stage}，以 SSE 流式返回该阶段执行事件 |
| POST | /api/lessons/[id]/confirm | body {stage, edits?}，教师确认后推进 status；edits 注入下一阶段 |
| POST | /api/lessons/[id]/reflect | body {results}（各题正确率），执行 reflect 阶段并写回记忆 |
| GET | /api/class-memory/[id] | 班级记忆详情与历史课列表 |
| GET | /api/lessons/[id]/export | 备课包 Markdown 导出 |
| GET | /api/health | 健康检查，Render 与保活服务使用 |

run 接口的响应头：`Content-Type: text/event-stream`，每个事件 `event: <kind>\ndata: <json>\n\n`，结束发 stage_done 或 error 后关闭流。

## 7. 知识库方案

一期检索采用"结构化过滤 + 文本包含"：先按 subject/grade 过滤，再对 text 做 LIKE 匹配，课标条目规模在百级，无需向量库即可稳定命中。二期接入 Turso 向量索引：种子数据生成时同步写入 embedding，检索以原生 SQL 建索引并按余弦相似度取 top-3（该部分不经 Prisma，封装为独立检索函数）。

课标条目示例（种子数据，节选整理自《义务教育语文课程标准（2022 年版）》公开文本，演示用途）：

```json
{ "id": "yw-34-read-2", "subject": "语文", "stage": "3-4年级",
  "code": "语文·3-4年级·阅读与鉴赏·2",
  "text": "能联系上下文理解词句的意思，体会课文中关键词句表达情意的作用。能初步把握文章的主要内容，体会文章表达的思想感情。" }
```

教材节点示例：

```json
{ "id": "yw-3x-hehua", "subject": "语文", "grade": "三年级", "volume": "下册",
  "lessonTitle": "荷花",
  "keyPoints": ["边读边想象画面", "体会优美生动的语句"],
  "prerequisites": ["比喻、拟人修辞的辨认", "自然段大意概括"],
  "commonErrors": ["概括段落大意时以偏概全，只抓细节", "想象画面停留在复述原文，缺乏个人体验"] }
```

题库按知识点与难度双标签组织，generate 阶段组题时优先取与 diagnose 弱点对应的知识点，实现"作业跟着学情走"。

## 8. 溯源与过程可视化

前端两处呈现：

1. 备课包页右侧溯源面板。每个教学目标、教学环节、作业题都带引用角标，点击展开 Citation 列表（类型、人读引用、原文片段）。
2. /prep/[id]/trace 页。按时间线展示 RunEvent：思考、工具调用、工具返回、校验、定稿。答辩时这一页直接证明"这是 Agent 在干活，不是模板拼接"。

## 9. 安全与合规落地

| 风险 | 落地措施 |
|---|---|
| 未成年人数据 | 产品仅面向教师；种子与演示数据全为模拟；上传成绩仅解析为"题号-正确率"，不存姓名学号，解析后原文即弃 |
| 替代教师判断 | 所有产物页脚与导出文件固定附"本内容供备课参考，教学决策由教师作出" |
| 内容安全 | 系统提示词内置价值观与课标一致性约束；generate 产物含敏感词规则过滤，命中转人工复核提示 |
| 提示词注入 | 教师输入以"用户提供的教学背景"角色注入，与系统指令隔离；工具入参做类型与长度校验 |
| 密钥 | LLM API Key 仅存 Render 环境变量，全部模型调用在服务端完成，客户端接触不到；会话签名密钥 SESSION_SECRET 独立配置（≥16 位），生产环境缺失即抛错拒绝降级运行，禁止从模型密钥派生（密钥用途分离） |
| 越权访问 | 课程与班级记忆的全部接口做资源归属校验（src/lib/lesson-guard.ts 统一守卫）：未登录 401、不存在 404、非属主 403；服务端页面（trace / print / 班级详情）同等拦截，非属主访问与不存在同响应，不泄露资源存在性 |
| 滥用 | /api/lessons/run 按 IP 内存限流（10 次/分钟） |

## 10. 部署架构

```yaml
services:
  - type: web
    name: qinglan-prep
    runtime: node
    plan: free
    buildCommand: npm ci && npx prisma generate && npm run build
    startCommand: npx prisma db push --skip-generate && npx tsx prisma/seed.ts && npm run start
    healthCheckPath: /api/health
    envVars:
      - key: NODE_VERSION
        value: "20"
      - key: TURSO_DATABASE_URL
        sync: false
      - key: TURSO_AUTH_TOKEN
        sync: false
      - key: LLM_BASE_URL
        value: https://api.deepseek.com
      - key: LLM_API_KEY
        sync: false
      - key: LLM_MODEL
        value: deepseek-chat
      - key: DEMO_MODE
        value: "true"
      - key: SESSION_SECRET
        sync: false
```

- 种子脚本幂等：先查 Teacher 是否存在，存在即跳过，保证每次部署不重复写数据。
- 冷启动：Render 免费档 15 分钟无流量会休眠，唤醒约 30-60 秒。用 UptimeRobot 每 10 分钟 ping /api/health 保活；落地页对首次加载慢给出"服务唤醒中"提示。保活 ping 只唤醒 Render 计算实例，Turso 无计算休眠概念，不产生额外费用。
- 数据库放 Turso 而非 Render 内置 Postgres：免费额度无计算时长限制、读请求无休眠、5GB 存储足够知识表与留痕数据，且本地开发与线上共用同一连接串，不受 Render Postgres 90 天生命周期限制。

环境变量表：

| 变量 | 说明 | 示例 |
|---|---|---|
| TURSO_DATABASE_URL | Turso libSQL 地址（CLI 使用时带 authToken 参数） | libsql://qinglan-prep.turso.io |
| TURSO_AUTH_TOKEN | Turso 访问令牌（运行时 adapter 使用） | eyJ… |
| LLM_BASE_URL | OpenAI 兼容地址 | https://api.deepseek.com |
| LLM_API_KEY | 模型密钥 | sk-… |
| LLM_MODEL | 模型名 | deepseek-chat |
| DEMO_MODE | true 时免登录，全部数据归属种子教师 | true |
| SESSION_SECRET | 会话签名密钥（独立于模型密钥，生产环境必须配置，≥16 位） | openssl rand -hex 32 生成 |

## 13. 评测体系

Agent 的"能力"不能靠演示截图自证，必须可量化、可复现。评测体系（`eval/` 目录）与产品同仓维护：

- **测的是产品本身**：评测运行器直接复用生产编排 `runStage`（同一份提示词、工具注册表、zod Schema 校验与持久化逻辑），不经任何旁路，杜绝"评测一套、产品一套"。
- **标准评测集**：3 个预置用例（课题四要素、学情描述、初始班级记忆、作业成绩 CSV 全部固定），刻意覆盖班级记忆的三种迁移路径——弱点仍显著时必须保留、空记忆新班级从零生长、弱点达标后正确消退并记入已解决。
- **断言全部可机检**：Schema 校验通过率、课标引用真实存在性（独立查库复核，不信任编排层兜底）、提示词要求的工具是否实际被调用（RunEvent 事件流）、记忆写回前后对比（ClassMemory 直接查库）、端到端 Citation/RunEvent 留痕数量。无人工打分。
- **独立评测库**：运行在本地 `prisma/eval.db`，与演示/生产数据完全隔离；知识库种子与线上一致。
- **一键复现**：`npm run eval` 自动初始化评测库 → 执行 3 用例 × 4 阶段 → 输出 `docs/评测报告.md`（人读汇总）与 `eval/reports/eval-<时间戳>.json`（机器明细）。报告含指标汇总、每用例断言明细表、方法与波动性说明，任何人运行同一命令可复现同一报告结构。

核心指标定义：阶段成功率（输出通过 Schema 校验并持久化的比例）、课标引用真实率、记忆写回正确率、工具调用覆盖率、端到端完成率、平均阶段耗时。
